Finance Tracker — living handoff (read/save to resume work)
===========================================================
Last updated: 2026-05-14

PURPOSE
-------
- Offline-first PWA: static HTML/CSS/JS, installable; PWA persists via `localStorage` (see `chromeStorage` adapter at top of `app.js`). Extension uses `chrome.storage.local`.
- Optional cloud: Google Apps Script backend; user deploys `google-apps-script.js` from repo root (keep in sync with `sync.js`).
- Mirror: `finance-tracker-chrome/` — same UI logic; `chrome.storage` + extension background for Sheets fetch (host_permissions avoid PWA POST/redirect body loss).

STACK
-----
- `index.html` — structure, most CSS, inline boot/lock handling, `BUILD_VERSION`, script tags with `?v=`.
- `app.js` — data model, persistence hooks, `fmt`, charts, `renderTxList`, `activateNavTab`, `EXP_CAT_GROUPS` (expense category groups for picker UI).
- `features.js` — global search (`#search-input`, `renderSearch`), optional auto-backup UI + daily trigger, dedupe for import, Ctrl+F → search on Expenses.
- `extras.js` — supplementary behaviours (keep in parity when touching related flows).
- `sync.js` — Sheet pull/push, chunked save path for large payloads on PWA.
- `import-inline.js` — TNG/UOB-style wizard; precached by SW.
- `service-worker.js` — `CACHE` name + `SHELL` list (must match files you ship offline).
- Recovery: `nosw.html` (clear SW/cache), `lock.html` (legacy redirect recovery; primary UX uses `#ft-boot` overlay in index).

NAVIGATION
----------
- SPA: one `index.html`; sections are `.page` blocks with ids `page-*` (only one has `.active`).
- Desktop: left sidebar `.sb` / `.sb-nav` shows all primary nav buttons.
- Mobile: `.sb` is a fixed bottom bar. Items with `data-mobile-overflow="1"` are hidden on small viewports; **More** (`#nav-more-open`) opens `#mobile-nav-more-sheet` for Recurring, Trends, Petrol, Report.
- **Import** (statement wizard + JSON backup) lives under **Settings**, not a top-level nav page.
- **Search**: “Search all months” card on **Expenses** only (`exp-global-search-card`); no separate Search page.
- Bottom nav uses `flex` / `space-between` for visible primary tabs (not scroll-snap in current CSS).

RECENT PRODUCT (verified in repo; omit rumours)
-----------------------------------------------
- Mobile-only “app shell” styling: elevated cards, pill controls, floating bottom nav capsule, dark “spent this month” hero — see `@media` blocks and comments around v16/v22 in `index.html`.
- Expenses (mobile): card order via flex `order` (add form first, stats, list, budget, chart); FAB scrolls to amount field; compact stat row.
- Expense category grid density adjusted (mobile CSS; comments reference column counts).
- Income list prefixes amounts with `+ `; **expense** list uses `fmt(amount)` only — **no leading minus** on list rows (pending if product wants “−RM …”).
- **Auto-backup** toggle + daily-on-open logic still present in `features.js` / Settings UI — **not removed**.
- PWA Sheets: large saves use chunked GET reassembly (see `sync.js` + deployed script); small payloads may use single GET save; redeploy Apps Script after backend changes.

IMPORTANT IDS / HOOKS
---------------------
- Pages: `page-expenses`, `page-income`, `page-assets`, `page-recurring`, `page-trends`, `page-settings`, `page-petrol`, `page-report`.
- Boot / readiness: `#ft-boot`, `#ft-boot-msg`, `ft-app-ready` (dispatched when app finished init).
- Tab switch: `activateNavTab('expenses'|...)` in `app.js` (toggles `.active` on `#page-<tab>` and nav buttons).
- Categories: `EXP_CAT_GROUPS` + `renderExpCatGrid` (and related) in `app.js`.
- Cache bust display: `BUILD_VERSION` in `index.html`; footer `#lk-ver` text set from it.

HOW TO CONTINUE
---------------
1. After changing any precached asset (`app.js`, `features.js`, `extras.js`, `sync.js`, `import-inline.js`, or shell HTML): bump **`BUILD_VERSION`** in `index.html`, bump **`const CACHE`** in `service-worker.js` (new string, e.g. `ft-v43`), and bump every local script query **`?v=`** in `index.html` to match.
2. If `google-apps-script.js` changes: user must create a new Apps Script deployment version.
3. Repo rule (`.cursor/rules`): when finishing a fix, `git add` relevant files, **commit**, **push** `origin/main` unless user says stop or push fails.

HISTORY / GOTCHAS (short)
-------------------------
- Past white-screen: unclosed `<style>` in head — entire body treated as CSS; always validate HTML structure after edits.
- iOS: avoid `body { position:fixed }` + nested scroll traps; prefer normal document scroll + bottom padding for nav.
- PWA POST to `script.google.com` can lose body on redirect; extension avoids this; PWA uses GET/chunk strategy.
